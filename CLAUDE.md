# YaoYao Dinner — Claude Guidelines

## Icons

- Use `lucide-react` for all icons. Never use raw inline SVG or SVG data URLs in className/style props.

## i18n

- Every user-visible string must use `useTranslation()` — no hardcoded strings in JSX.
- Add keys to all four locale files: `frontend/public/languages/{en,vi,zh,th}.json`.
- Update `frontend/src/i18next.d.ts` with any new keys.

## Theme & colors

- **Never hardcode color values** (hex, oklch, rgb, or Tailwind palette colors like `orange-500`).
- Use semantic Tailwind tokens that map to CSS variables: `bg-primary`, `text-primary-foreground`, `bg-accent`, `bg-muted`, `text-muted-foreground`, `bg-destructive`, `border-border`, etc.
- For brand-specific utilities not covered by default tokens, add CSS custom properties to `frontend/src/global.css` under `@theme inline` and use those (e.g. `bg-brand-muted`).
- To change the site theme, edit only `frontend/src/global.css` — components must never need touching.
- The current theme is **purple** (`--primary` hue ~305 oklch). Do not introduce unrelated palette colors.

## Component structure

- Keep `page.tsx` thin — it wires hooks and renders sub-components.
- Extract each logical section into a co-located `@ComponentName.tsx` file in the same page folder.
- No boilerplate comments, no unused imports, no dead code.

## Generated files

- Do **not** edit files under `frontend/src/api/` — they are generated by orval from `openapi.json`.
- To add/fix types: update the backend DTO + `@ApiResponse`, patch `openapi.json`, run `task generate`.

## Env vars

- Runtime config lives in `frontend/.env` (gitignored) and `frontend/.env.example` (committed).
- Access via `import.meta.env.VITE_*` with a production fallback in `frontend/src/common/app.ts`.

## Code style

- No inline comments unless the reason is non-obvious.
- Use `cn()` from `@/utils/shadcn` for conditional class names.
